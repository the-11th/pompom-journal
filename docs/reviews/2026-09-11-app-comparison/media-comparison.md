# Mobile photos, places, and shared controls: ORIGINAL vs QA

This is a read-only comparison of the exact extracted APK assets in `/tmp/datapom-app-comparison/original/assets/journal` and `/tmp/datapom-app-comparison/qa/assets/journal`. No source, app, or user data was changed. Findings below come from the asset code and styles, plus a small pure-function differential using synthetic objects. This pass did not operate either installed app.

Both builds already contain the main photo editor, photo tagging, Photos view, daily Places/replay, saved places, tracking controls, and offline-map status. QA chiefly improves presentation, validation, recovery, and focus. It does not introduce photo editing or offline maps from scratch.

The mobile loader reaches `M.photos` for Photos, mounts `PupLocationDayView` directly for Places, and calls `M.settings` for Photos & places settings. See [ORIGINAL navigation](/tmp/datapom-app-comparison/original/assets/journal/mobile-journal.js:9) and [QA navigation](/tmp/datapom-app-comparison/qa/assets/journal/mobile-journal.js:10). Entry typography, entry tag fields, native task/gallery implementation, and the USB protocol are covered separately by the parent/native comparison.

## Shared capabilities and unchanged boundaries

- Both support drawing, text, stickers, manual trace/cutout/refine, crop/reset, 90° photo rotation, sticker resize/rotation/removal, and Undo/Redo. Both save a derived image with the original asset reference and editing layers; these are not QA-only features. The pure editing helper code before `stickerMaker` is unchanged. [Original save pipeline](/tmp/datapom-app-comparison/original/assets/journal/photo-edit.js:25), [QA save pipeline](/tmp/datapom-app-comparison/qa/assets/journal/photo-edit.js:25).
- Both support photo captions, show/hide caption, linked-text-only display, photo tags, location label/color/visibility, location correction, taken time, full/medium/small width, linked text passages, insert ordering/removal, and a read-only viewer. Removing an insert keeps the original in the library in both. [Original details/editor](/tmp/datapom-app-comparison/original/assets/journal/media-ui.js:328), [QA details/editor](/tmp/datapom-app-comparison/qa/assets/journal/media-ui.js:488).
- Both Photos and Places cards open read-only previews. Edit photo / Photo details appear through the editable journal’s viewer callback. Seeing different controls through these two entry points is not evidence that either build lacks editing. [Original viewer](/tmp/datapom-app-comparison/original/assets/journal/media-ui.js:308), [QA viewer](/tmp/datapom-app-comparison/qa/assets/journal/media-ui.js:477).
- Both have offline vector maps, touch pan/pinch, keyboard pan/zoom, coverage, saved/starred places, city/wider-area labels, archive/restore, My location / Star here, daily route replay, device filters, stopped/moving summaries, and capture-time photo placement. `location-day.js` is byte-identical, so this comparison does not show changed underlying movement/stop calculations.
- Both mobile settings show USB map transfer/status and “Set up Discord on your Mac.” Download/Update/Check size/Add map area and Discord receiver setup/sync controls are explicitly guarded by `!window.TodoPupNative`; their QA improvements are excluded from mobile feature claims. [QA map branch](/tmp/datapom-app-comparison/qa/assets/journal/media-settings.js:333), [QA Discord branch](/tmp/datapom-app-comparison/qa/assets/journal/media-settings.js:369).

## Reproduced helper differences and limits

A read-only Node comparison loaded each exact `media-ui.js` export with the same three synthetic entries: photo A on September 1 with an older caption; photo A on September 3 with a newer caption; and photo B attached only to text on September 2.

| Result | ORIGINAL | QA |
| --- | --- | --- |
| Unique photos | 1 | 2 |
| Photo A representative | September 1 / Older caption | September 3 / Newer caption |
| Photo B, text link only | Absent | September 2, included |
| Unknown caption `@constructor` with an empty tag catalogue | Produces an invalid tag-group entry | Produces no tag |

These checks establish the helper differences, not a device screenshot comparison. Layout dimensions above are CSS values, not fresh on-device measurements. Native photo selection, platform permissions, storage/sync guarantees, and native handling of revision/Back notifications require the separate native review. Original Android source was used only to confirm the existing loader/Back bridge path; exact APK assets remain the evidence for the shared UI comparison. No claim here relies on the current working-tree version matching either installed APK.
